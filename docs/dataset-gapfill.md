## TTS gap × candidate table

Fighter langs with zero prompt-set dataset: **an** (Aragonese), **ast**
(Asturian), **fy** (Frisian), **oc** (Occitan).

TTS prompt sets need *text-only* prompt corpora (the existing
`intents-for-eval-prompts` / `massive-prompts` pattern), not audio+
transcript pairs, FLEURS/CommonVoice don't fit this shape directly (they
could supply *reference transcripts as prompt text*, but that's a
different registration pattern than the existing two TTS datasets use,
and no loader precedent for it exists in any mined repo).

Partial note: `ast_es` and `oc_fr` *do* exist as FLEURS STT configs (see
table above), so their transcripts are a plausible prompt-text source if
someone wants to build a `fleurs-derived-prompts-<lang>` TTS dataset. This
needs a new loader path (extract `transcription` field only, drop audio),
which is a code change, not a JSON-only addition.

**Not registered this batch**, flagged for a follow-up PR since it needs a
`benchmarks/` script change, which is out of the "JSON-only easy win"
scope for this PR.

No ready HF source found for **an** or **fy** in any mined repo.

## What this PR registers

10 new `registry/datasets/stt/fleurs-<lang>.json` entries: ar, as, bn, cs,
da, fa, gu, hi, or, sd. All follow the existing `fleurs-ca.json` /
`fleurs-gl.json` schema exactly (`source.type: huggingface`,
`hf_id: google/fleurs`, `subset: <fleurs_config>`, `split: test`,
`reference_fields: {audio, ground_truth: transcription}`,
`license: cc-by-4.0`, `role: eval`).

**None of these have a board yet**, `predictions_hf` names a HF repo
(`OpenVoiceOS/ovos-stt-bench-fleurs-<lang>`) that does not exist. Per
`dataset-review.md`'s own terminology, these are "registered but idle"
until:

1. the `OpenVoiceOS/ovos-stt-bench-fleurs-<lang>` HF dataset repos are
   created (10 repos: ar, as, bn, cs, da, fa, gu, hi, or, sd)
2. a `benchmarks/*.py` script (or an extended `stt_minds14.py`-style
   matrix) is pointed at each new dataset id so fighters actually get
   scored against it

This PR is data-registration only, no `benchmarks/` script changes, no
board publishing, per the "JSON-only, no preprocessing" scope for an easy
win batch.
